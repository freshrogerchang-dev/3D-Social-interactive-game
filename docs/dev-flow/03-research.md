## 1. 需求與待確認事項

### 1.1 本次收斂的 MVP 情境需求（沿用 S1 建議，尚未獲使用者批准）

1. 一個公園，加一個安全區。
2. 一位 NPC，固定坐著，不主動靠近玩家、不追隨玩家、不搶先開口。
3. 只有玩家明確按下「打招呼」才開始互動。靠近 NPC 不會自動彈出對話。
4. 兩種平等有效的回應：「說你好」和「點頭」。兩者的回饋語氣、後續選項與結果完全相同。
5. 另外提供：幫助、先不參與、返回安全區（退出）、再練一次（重試）、換一種方式（修復）。
6. 沒有限時、評分、星等、懲罰、排名，也不要求眼神接觸。
7. 結果只分三類：`finished`（完成打招呼）、`skipped`（先不參與）、`exited`（返回安全區）。結果只存在記憶體，不累計，不儲存兒童歷史（沿用 S1 資料最小化）。

一般細節採用的合理預設（未經使用者確認，可推翻）：
- NPC 暫名「小安」，性別不設定。藍圖範例是「小明（男孩）」，命名與外觀交由文化審查。
- 對話文字一次完整顯示，不逐字跳出，也不自動前進。
- 返回安全區不跳確認視窗：一次操作就生效，以免增加離開的門檻。誤觸可在安全區按「回公園」回來。這點要請專業審查確認。
- 草案只用繁體中文（台灣用語），不做多語系。

### 3.2 狀態與節點

暫定字數上限（Q1 確認為 5–8 歲後下修；仍是假設，待審查）：NPC 台詞 ≤10 字，系統提示 ≤12 字（一行），按鈕標籤 ≤4 字。每個字都附注音；每段台詞、提示與按鈕標籤都有語音（§9.1、§9.3）。圖示一律附文字，不能只用圖示。目前部分提示超過新上限，要在 v0.2 縮短。

**場景狀態（對話外）**

|---|---|---|

**對話節點**（所有對話節點另有：幫助 → 原節點、暫停 → 原節點、返回安全區 → `END_EXITED`）

|---|---|---|---|
| `N1_GREET`（根節點） | 小安：「你好。」語氣標籤：平靜。動作：小幅揮手一次（降低動態時只顯示揮手圖示） | 「你想怎麼回應？」 | 說「你好」（圖示：對話泡泡） → `N2_SPOKEN`；點頭（圖示：點頭的頭像） → `N2_NOD`；先不參與 → `N_NOT_NOW`；再看一次 → 原節點（重新顯示台詞，若有語音則重播） |
| `N2_SPOKEN` | 小安：「你好。我在這裡休息。」 | 回饋：「你說了『你好』。小安回應了你。」 | 結束打招呼 → `END_FINISHED`；再練一次 → `N1_GREET`；換一種方式 → `N_REPAIR`；再看一次 → 原節點 |
| `N2_NOD` | 小安點點頭：「你好。我在這裡休息。」 | 回饋：「你點頭打招呼。小安回應了你。」 | 與 `N2_SPOKEN` 完全相同 |

**結束與返回**

| 節點 ID | 結果 | 畫面文字（草案） | 可用動作 → 目標 |
|---|---|---|---|
| `END_FINISHED` | `finished` | 「這次打招呼結束了。」 | 再練一次 → `N1_GREET`；回安全區 → `SAFE_ZONE` |
| `END_SKIPPED` | `skipped` | 「你回到公園。小安還在長椅上。」 | 回公園 → `PARK_OBSERVE`；回安全區 → `SAFE_ZONE` |

### 3.4 回饋語原則

- 描述行為，不評價人：用「你點頭打招呼」，不用「你很棒」「答對了」。
- 兩種回應的句型逐字對稱，只有動作詞不同。
- 不預告 NPC 的情緒後果。藍圖的 `previewConsequence`（例如「小明會理解你比較安靜」）會替玩家貼標籤，MVP 不採用。
- 不出現「失敗、錯誤、可惜、再努力」。

### 3.6 路徑與引用檢查

在 scratchpad（專案外）用 Python 寫了這張狀態圖的檢查腳本並執行，結果是 `ALL CHECKS PASSED`：12 個狀態全部可從 `SAFE_ZONE` 到達。檢查項目：

1. 所有轉移目標都存在，沒有懸空引用。
2. 所有狀態都可以從 `SAFE_ZONE` 到達。
3. 所有狀態都能回到 `SAFE_ZONE`，沒有死路。
4. 每個對話節點都有「幫助」（目標為自身）與「返回安全區」（目標為 `END_EXITED`）。
5. 「返回安全區」與「先不參與」都不會進入 `END_FINISHED`。
6. `N2_NOD` 與 `N2_SPOKEN` 的後續轉移完全相同。
7. 沒有任何計時類轉移。

限制：這只是設計層級的狀態圖檢查，沒有檢查台詞內容是否合適，也不是遊戲程式的測試。後續 Phase 4 實作時，應把同樣的規則寫成正式的內容驗證測試（見 §7）。

### 6.2 停止準則（草案，待臨床專業審查）

**單次評估立即停止：**
- 兒童用任何方式表示不想繼續，包括口語、手勢、轉身、離開座位，或照護者解讀的個別訊號。

**整體評估暫停並回到審查：**
- 任何一次出現不適或不良事件。
- 審查者或照護者認為內容可能造成傷害。
- 發現資料蒐集超出核准範圍。

**不是停止理由，也不能記為負面結果：** 兒童使用「先不參與」或「返回安全區」，或從頭到尾不打招呼。這些是設計中被允許的選擇。

- 每段音檔記錄台詞、模型、音色、提示的雜湊，並檢查音訊長度；全部齊全且雜湊相符才匯入。
- 達到每日免費上限時停止並保留進度，隔天續做。
- 生成成功不等於驗收：要人工試聽（口音、漏字、指令被唸出、音量、語氣）。

**官方文件（[Gemini speech generation](https://ai.google.dev/gemini-api/docs/generate-content/speech-generation)，頁面標示 2026-10-01 更新，查閱 2026-10-08）**

- 目前列出 `gemini-3.8-flash-tts`、`gemini-3.8-flash-lite-tts`（GA），以及 preview 模型。

- 輸出為 24 kHz、單聲道、16-bit PCM（WAV）。

**語音設計建議（待審查）**

- 所有台詞、提示、按鈕標籤、幫助內容都有語音；進入節點時自動播放一次（由兒童的動作觸發，不違反瀏覽器自動播放限制），並有「再聽一次」。
- 「說你好」與「點頭」對等：選「說你好」時播放角色說「你好」，選「點頭」時播放點頭動作與相同長度的提示音或旁白，兩者都由審查確認。
- 音量正規化，避免突然的大聲；語音、音效、背景音分開調整；隨時可靜音，靜音後文字、注音與圖示仍完整可用。
- 音檔 manifest 記錄：節點 ID、台詞全文、注音、音檔雜湊、生成模型或錄音者、審查狀態。審查以「內容版本＋音檔雜湊」為單位（§5.4）。

### 9.5 Q6：高度寫實（使用者已於 2026-10-08 決定）

使用者在三個選項（寫實比例＋簡化質感、高度寫實、卡通風格）中選擇**高度寫實**。本文件原本建議「寫實比例＋簡化質感」；以下依使用者決定調整，不推翻任何安全不變條件。

**為什麼高度寫實可能有幫助（假設，未驗證）**：場景越像真實公園，練習經驗可能越容易類化到現實生活。這是推論，§2 的文獻沒有直接比較寫實程度與類化效果的證據，要列入專業審查的問題。

**與既有規則的關係**

| 既有規則或風險 | 處理方式（待審查） |
|---|---|
| S1 的保守色彩預設（HSL S ≤ 0.6）、不閃爍、不模糊、不晃動（§3.1、§4.5） | 繼續有效。寫實指的是形狀、比例、材質與光線物理正確，不是高飽和或強烈對比；不用 bloom、景深模糊、動態模糊、鏡頭光暈、畫面雜訊 |
| R3、R4：感官偏好有個別差異 | 設定提供「細節程度」（高／中／低）：可降低貼圖細節、關掉陰影、減少背景物件與動態植物。預設值由職能治療審查決定 |
| 寫實人物的恐怖谷 | 環境可高度寫實；NPC「小安」採寫實比例與自然動作，但臉部不追求照片級，表情幅度小且一致。是否加高臉部擬真度，交由專業審查與兒童評估後再決定 |
| 不要求眼神接觸（§3.1） | 寫實 NPC 不做持續注視玩家的視線追蹤；NPC 的視線自然、可轉開 |
| 背景人物與動態 | MVP 公園只有小安一個 NPC；不加入路人、車輛、寵物等不可預測的動態。風吹樹葉等環境動態要很小，且「降低動態」開啟時停止 |
| 聲音 | 寫實環境音（鳥叫、風聲）預設很小聲，可單獨關閉；不放突然的聲音（狗叫、喇叭） |

**技術影響（S2 尚未驗證，列為後續核對）**

- Renderer：`MeshStandardMaterial`／`MeshPhysicalMaterial`（PBR）、sRGB 輸出、ACES 或 AgX 色調映射、HDR 環境貼圖做環境光。這些是 Three.js 內建功能，骨架可先設定好管線，不需要額外套件。
- 素材：glTF/GLB；貼圖用 KTX2（Basis）壓縮、模型可用 Draco 或 meshopt。這會在 Phase 7 引入 loader 與轉檔工具，屆時要另外核對版本、授權並取得安裝授權。
- 素材來源：優先 CC0（例如 Poly Haven、ambientCG）；每個素材記錄來源網址、授權、作者與修改內容。寫實人物模型的授權通常更嚴格，要個別確認。
- 效能：寫實光影對平板負擔大。建議的預算（待 S5 實機量測）：目標平板穩定 60 FPS、最低 30 FPS 不掉幀抖動；首次載入素材總量先以 50 MB 為上限；陰影只用一盞方向光、解析度可隨細節程度調整；`devicePixelRatio` 上限 2。數字是起點，不是驗收結果。
- 美術製作量：高度寫實比簡化風格需要更多建模、貼圖與調整時間，可能讓 Phase 7 與 Phase 9 變長。

**對 S4 第一里程碑的影響**

- 範圍**不變**：仍只做 Phase 0 + Phase 1 骨架，不載入外部素材。
- 骨架的 renderer 先設定成寫實管線可用：sRGB 輸出、色調映射、物理正確光照與一盞柔和的方向光；地面與安全標記可用簡單 PBR 材質。
- 不加入任何後製效果；不加入細節程度設定的 UI（屬 Phase 6–7），但設定物件要預留 `detailLevel` 欄位。

**要加入專業審查（§5.2）的問題**

- 高度寫實的環境與 NPC 外觀，對 5–8 歲兒童是否造成過多刺激或不安？
- 細節程度的預設值應該是多少？
- 寫實公園的配置（遊樂設施、長椅、樹）是否符合台灣兒童熟悉的公園樣貌？
