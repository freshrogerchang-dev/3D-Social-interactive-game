## 1. 使用者指定範圍與授權

- 使用者要求「增加其他的一些場景跟練習社交的對話」。逐項確認後的範圍：
  - 練習主題：**請問可不可以一起玩**、**輪流排隊**、**放學不想去游泳課**（使用者原話：「放學了，自己很想回家玩玩具但是要去上游泳課，這時候要跟爸媽說今天不想去游泳課，爸媽跟我說去游泳完，回家可以玩switch」）。

- 沒有安裝或升級套件，沒有新增設定檔，`package.json`／`package-lock.json` 不變。

### 公園配置

出發點 (0, 3.5) 面向 -z，所有人都在前方，彼此距離大於靠近範圍（> 6.4 m），一次只會靠近一位：

| 人物 | 位置 | 情境 | 開始按鈕 |
|---|---|---|---|
| 小安（坐在長椅） | 正前方 (0, -2) | 打招呼（原有） | 打招呼 |
| 小宇（站著、拿球） | 左前 45° (-6.5, -3) | 一起玩 | 跟小宇說話 |
| 小晴（站著排隊） | 右前 45° (6.5, -3)，溜滑梯在她前方 | 排隊 | 去排隊 |
| 媽媽（站在入口內） | 最遠端 (-1.2, -8.6) | 游泳課 | 跟媽媽說話 |

手機直向的水平視野只有約 ±15°，所以小宇、小晴放在出發點左右 45°：轉三次「向左／右看」，人物就在正前方。人物朝向固定，不追蹤玩家視線。

### 對話內容摘要（v0.1 待專業審查草案）

共同規則（每條都有測試）：對方不先開口；說的與動作的選項得到完全相同的回應與後續；幫助保留原節點；沒有計時、評分或評價語；「先不參與」記為 skipped，返回安全區記為 exited，都不算失敗；每條路都能回公園。字數：台詞 ≤ 10、提示與幫助 ≤ 12、選項 ≤ 4、一個畫面最多 4 個選項。英文單字（Switch）算一個詞。

- **一起玩（小宇）**：問一起玩／用手指球／先看一下／先不參與 → 小宇「可以。等我踢完這球。」→ 說好或點頭等待，或說「現在就玩」（小宇：「我踢完就換你。」）→ 一起踢球。完成後可選「換個回答」練習被拒絕：小宇「現在不行，在比賽。」→ 說好或點頭（等一下再問）／去玩別的／說我難過（「難過是可以的。可以去做別的事。」）。
- **排隊（小晴）**：排在後面／問排隊嗎／先不參與 → 小晴「我先溜，再換你。」→ 說好或點頭 → 輪到你溜下去。完成後可選「有人插隊」：說請排隊／指向後面／找大人／讓他先溜，四種都可以選，結果都能輪到自己。
- **游泳課（媽媽）**：媽媽「我們等一下去游泳。」提示「你想回家玩玩具。」→ 說不想去／搖頭／說想回家／先不說 → 媽媽複述你的想法（「你今天不想去游泳。」或「你想回家玩玩具。」）→ 說對或點頭 → 媽媽「謝謝你告訴我。」→ 聽媽媽說 → 「先游泳，再玩Switch。」→ 說好或點頭／還是不想／想先休息。「還是不想」時媽媽說「你還是不想去。」並提示「可以說你需要什麼。」；可選休息、同意或先不說，沒有強迫的單一路線。

建置過程中發現並修正：

- 第一版人物在出發點左右兩側，手機直向靠近時人物不在畫面內，媽媽在出發點背後。改為所有人在前方，小宇、小晴在左右 45°。
- 小晴原本面向溜滑梯，走近時只看到後腦，改為固定側身朝向公園中央。
- 「練習插隊」可能被讀成「練習去插隊」，改為「有人插隊」。「和」在台灣有 ㄏㄜˊ／ㄏㄢˋ 兩種讀法，改用「跟」。疊字「指指」「搖搖頭」「看看」改寫，避免輕聲判斷。
- 瀏覽器腳本本身的問題（非產品問題）：設定裡的單次移動按鈕是「走向目標點」，連按會取代目標；收合設定會非同步清除移動輸入。腳本改成每步等待、收合後稍等再按鍵。

## 4. 未驗證與待審查

- **專業內容審查（必要）**：三個新情境的語句、選項、回應方式，特別是：被拒絕時的回應與「難過是可以的」說法；插隊時「找大人」「讓他先溜」等選項是否合適；游泳課的「先游泳，再玩 Switch」約定、媽媽複述感受的說法，以及「還是不想」之後的處理。
- **注音審查**：新增 97 個字與兩個疊字詞為人工標註。待確認：「一」「不」標本調的慣例；既有「休息」的「息」標 ㄒㄧˊ（本次沿用，未更改）；「告訴」的「訴」標 ㄙㄨˋ。
- **人物外觀**：站姿沿用坐姿的手臂（前臂在身體前方）與臀部造型，看起來像捧著東西；四位人物共用同一張臉部貼圖；媽媽是小孩模型放大 1.3 倍。這些是工程原型，待使用者與專業外觀評估。
- **實機**：iPhone 12 Safari／Chrome 尚未測試新版（移動到各人物、對話排版、效能）。軟體 WebGL 結果不代表實機效能。
- 語音仍未製作（Q3 語音另做）；VoiceOver、原生文字 200%、跨瀏覽器仍未驗證。
